*=============================================
* MODLD - load a relocatable module
*
* A module is assembled at ORG 0, so it can be
* dropped anywhere. Its file begins with a ten
* byte header of OFFSETS, then the code image,
* then a list of places inside that image which
* hold an address and therefore need the load
* address added to them.
*
*   +0  da m_last    newest word in the module
*   +2  da m_first   oldest word, link patched
*   +4  da m_len     bytes in the image
*   +6  da m_init    routine to call once
*   +8  da m_nrel    how many fixups follow
*   +10 the image
*       then m_nrel two-byte offsets
*
* Only addresses INSIDE the module need fixing.
* References to the kernel go through the jump
* table, and references to fixed hardware are
* fixed. Branches are relative and never move.
*
* Exit: carry set if the file would not load.
*=============================================
modld jsr setpth
 jsr openf
 bcc mlopok
 sec                    ; no such file
 rts

*=============================================
* getkey - a key, and some entropy with it
*
* The machine has no clock and no noise. What
* it does have is a person, and people are not
* punctual. While the monitor waits for a key
* it counts, over and over, in $4E and $4F; by
* the time a key arrives that count holds the
* low bits of how long the wait was, which is
* the one thing about this machine nobody can
* predict.
*
* So every keystroke stirs the generator. A
* program that asks for a random number after
* the user has typed anything at all starts
* from somewhere unrepeatable - and one that
* wants the SAME game twice can say SEED.
*=============================================
getkey jsr rdkey
 pha
 lda rndl
 eor rnd+2
 sta rnd+2
 lda rndl+1
 eor rnd+3
 sta rnd+3
 pla
 rts
*=============================================
* rndnxt - sixteen more random bits
* out: A = high byte, Y = low byte
*
* A 32-bit shift register whose feedback taps
* make it run through all 4,294,967,295 states
* before it repeats. The taps matter: pick the
* wrong ones and it still looks random, still
* passes a casual glance, and quietly cycles
* after a few thousand draws. These are for
* x^32 + x^7 + x^5 + x^3 + x^2 + x + 1, which
* is a primitive polynomial - and every tap
* below eight, so the feedback touches one
* byte instead of four.
*
* All zeroes is the one state it cannot leave,
* so that is checked rather than hoped about.
*=============================================
rndnxt lda rnd
 ora rnd+1
 ora rnd+2
 ora rnd+3
 bne rndn1
 lda #1                 ; a dead register stays dead
 sta rnd
rndn1 ldx #16
rndn2 asl rnd
 rol rnd+1
 rol rnd+2
 rol rnd+3
 bcc rndn3
 lda rnd
 eor #$af               ; the taps, all in one byte
 sta rnd
rndn3 dex
 bne rndn2
 lda rnd+3
 ldy rnd+2
 rts

* binld - read a binary file in at DP
*

*=============================================
* DOVAR - what a CREATEd word does
*
* A word made by CREATE has this shape:
*
*   link  len  name  CFA  DOESP  data...
*
* CFA points here, DOESP is the cell DOES>
* fills in, and the data begins four bytes past
* the code field. So all this has to do is push
* W+4 - the address of the word's own data.
*=============================================
dovar clc
 lda w
 adc #4
 sta t1
 lda w+1
 adc #0
 ldy t1
 jsr push
 jmp next
*=============================================
* DODOES - what a word made by a DOES> defining
* word does
*
* Push the data address exactly as DOVAR would,
* then go and run the FORTH that followed DOES>
* in whatever word created us. Which is DOCOL's
* job with one difference: the code to run is
* not at W+2, it is the address STORED at W+2.
*=============================================

 sta t1
 lda w+1
 adc #0

 jmp next
*=============================================
* DODO - the runtime DOES> compiles
*
* Runs while the DEFINING word is executing,
* just after it has CREATEd something. Two
* stores and a return:
*
*   the new word's code field  ->  DODOES
*   the new word's DOESP cell  ->  IP
*
* IP is pointing at whatever follows DOES> in
* the defining word, which is exactly the code
* the new word should run. Then we exit the
* defining word, because everything after DOES>
* belongs to the child and not to the parent.
*=============================================

 sta t1+1

 sta (t1),y
 iny

 sta (t1),y

 sta ip
 pla
 sta ip+1
 jmp next

*=============================================
* RND ( lo hi -- n ) a number in a range
*
* Inclusive at both ends: 1 6 RND rolls a die.
*
* The obvious way to fit a random number into
* a range is to take the remainder after
* dividing by it. This does not divide. It
* multiplies the random number by the size of
* the range and keeps the HIGH cell of the
* 32-bit product - which is the same thing as
* asking what fraction of the way through the
* range the random number falls. No division,
* and it reuses the UMUL from Part 7.
*
* HI must not be less than LO. Reversed, the
* range comes out as a huge unsigned number
* and the answer is meaningless.
*=============================================

 sta t1+1

*
* Everything after DOES> in a definition

* the words IT will define. Compiling it is one
* cell; the work happens at run time, in DODO.

* part of CONSTANT at all - it runs later, and
* every time, in each of CONSTANT's children.

*=============================================
* RUN ( a -- ) load and run a named file
*
* LOAD takes its name from the text being
* interpreted, which is no use to a program
* that worked the name out for itself. RUN
* takes a counted string from the stack
* instead. Everything after that is LOAD.
*
* The name is copied into PATH first, because
* the file is about to be interpreted and its
* definitions will land on top of the table the
* name came from.
*=============================================
h_run da h_dir
 dfb 3
 asc "RUN"

 lda t1
 ldy t1+1
 jsr setnam
